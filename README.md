# SideQuest

**Your next adventure is outside this app.**

Most apps compete to keep you looking at them. **SideQuest uses AI to make itself unnecessary.** It turns 15, 30 or 60 minutes into a small outdoor quest. Choose a mood and an environment, get 2–3 observation tasks, put your phone away, then return with one photo and the things you noticed.

[Try SideQuest](https://side-quest-ai.onrender.com) · [Source code](https://github.com/ankitks1209/Side-quest)

Built for the [DEV/Hacktoberfest 2026 Week 1 “Touch Grass” challenge](https://dev.to/challenges/hacktoberfest-week1-2026-10-05). The world is the interface: the screen should be the shortest part of the experience.

## How it works

1. Choose **15 / 30 / 60 minutes**, **Explore / Relax / Move / Notice**, and **City / Park / Anywhere**.
2. Read a quest generated by **Gemma 4 26B**. Every quest has exactly one photo task; the other tasks are self-reported.
3. Tap **Begin SideQuest**, put the phone away and explore from safe public paths. Skip anything unsafe in your surroundings.
4. Return, upload one photo and mark the other tasks you completed. **Gemini 3.7 Flash** checks the photo against its single task criterion.
5. See your discoveries, verification receipt and measured **Away Ratio**.

Exactly five primary screens: Landing → Quest Setup → Quest (including active state) → Evidence → Completion. No account, maps, GPS or exact location is required.

## AI with a small, explicit job

Gemma is the open-weight core. Hosted `gemma-4-26b-a4b-it` generates quest JSON through Google's Interactions API. The app parses and checks schema, approved primitives, input compatibility and deterministic safety rules before displaying a quest. Rejected output or provider failure gets one retry, then a curated fallback passes the same approval boundary. The UI identifies a backup quest.

Gemini `gemini-3.7-flash` is a separate, bounded multimodal verifier; it is **not the open-weight core**. Uploads must be JPEG, PNG or WebP, no larger than 5 MB, with matching MIME and file signature. A photo counts only when a validated result says `verified: true` with confidence ≥ 0.75. Uncertain results and technical failures allow completion without counting the photo. Technical failures retry once.

**AI proposes; deterministic application code decides what SideQuest accepts.**

```text
Preferences → Gemma → raw structured output → JSON extraction
→ Zod schema / approved primitives → input compatibility
→ deterministic safety validation → approved Quest
```

The safety rules reject specified hazards including trespassing, rail tracks, unsafe traffic, construction areas, unsafe heights, water entry, wildlife handling, unknown plant/fungi consumption and dangerous night exploration. The safety gate is a tested rule-based filter, not a guarantee that all generated language or outdoor conditions are safe. Photo verification checks visible content; it does not prove location, capture time or that a user went outside.

## What Away Ratio measures

Timing runs from **Begin SideQuest** to completion, including the return and evidence steps. SideQuest accumulates time while its document is visible; the rest is estimated away time.

```text
estimatedAwayMs = max(0, elapsedMs - clampedVisibleMs)
Away Ratio = estimatedAwayMs / elapsedMs
```

A zero-duration session returns zero. Elapsed time is not capped at the selected quest duration. Refresh recovery discards an interrupted visible segment and can overestimate away time. A hidden SideQuest tab could mean another app, not outdoor activity: this is an **app-visibility estimate, never device-wide screen time**. It is a reflection on the session, not proof of reduced phone use.

## Data and privacy

- Model calls and the API key stay on the server. Both Google requests use `store: false`; no provider conversation state is used.
- SideQuest does not persist or log image bytes. Uploaded photos are sent to Google for verification; `store: false` disables Interaction storage and is not a claim of zero provider retention under all policies.
- localStorage holds validated setup preferences and one active quest/session recovery record, including task progress and verification results. Active/Evidence reloads recover without the photo. Completion clears active recovery; there is no completion history or database.

## Run locally

Use **Node.js 24.x** (see `.nvmrc`) and npm. Versions are pinned in the committed lockfile.

```sh
npm ci
cp .env.example .env.local
npm run dev
```

Open [localhost:3000](http://localhost:3000). Set `GEMMA_API_KEY` in `.env.local` for real generation and photo verification. Optional model and endpoint overrides use the defaults in the server adapters when omitted:

| Variable | Purpose |
| --- | --- |
| `GEMMA_API_KEY` | Server-only Google key used by both adapters; never use `NEXT_PUBLIC_` |
| `GEMMA_MODEL` | Optional quest-model override |
| `GEMMA_BASE_URL` | Optional Google API base-URL override |
| `VISION_MODEL` | Optional evidence-model override |

Without a working key, generation returns an approved curated fallback and verification is unavailable; completion still works. Hosted AI requires internet and provider access. Local inference is not implemented.

## Render deployment

The live app runs as one **Render Node Web Service**. Render hosts the Next.js UI and server API routes; Google hosts model inference. No database or persistent disk is used.

```text
Branch: main
Build command: npm ci && npm run build
Start command: npm start
Health check path: /
```
